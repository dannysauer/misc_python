# hvac-predict quality attributes

> **Summary:** The requirements the tool must keep, each with a stable ID that the tests name. A test that verifies a requirement carries its ID in a comment.

Requirements use the keywords in [BCP 14](https://www.rfc-editor.org/info/bcp14): MUST, MUST NOT, SHOULD, SHOULD NOT, and MAY, which carry that meaning only in capitals. IDs never change and are never reused; a retired requirement keeps its ID with a note saying why it was retired.

Test names below are relative to `tests/`. Every test listed has run only against simulated houses and stand-ins for the two services, so "verified" here means verified against what the code assumes about them.

## Choice of setpoints

HVP-003 and the cooling half of HVP-004 come from the owner's rule, in the [settling record](../adrs/2026-11-15-give-a-new-target-time-to-be-reached-unaided.md). The owner's example for HVP-003 is a target that drops; the first request asked for the same when the house will warm up by itself. HVP-005, HVP-006 and HVP-015 come from the [proposed completions](../adrs/2026-11-15-complete-the-rules-where-the-owners-are-silent.md), as does the warming half of HVP-004. They describe what the code does now and change if that record does.

HVP-008 is not met to the minute. The code counts the 20 minutes back from the newest five-minute mark, which can be almost five minutes before the run; see [open question 25](overview.md#about-operation).
